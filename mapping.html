"Three questions every navigation system must answer: Where am I? What's around me? How do I get there?"

Goal

Autonomous maze exploration and return-to-start on a hexapod using only sonar sensing and dead reckoning, with no prior map

Role

Programmer

Skills

Dead Reckoning Sonar Sensing Path Planning Depth-First Search Python Real-Time Mapping

Outcome

Explored about half the maze · sonar false positives reduced with median filtering · drift bounded by landmark-based origin detection

Given an unknown maze and no prior map, the robot needed to explore every reachable corridor and build a grid map of what it found. The challenge was doing this with a single sonar sensor sweeping 270° and no external localization: no GPS, no camera, no preloaded layout. The robot had to decide where to go, track where it had been, and know when it was done, relying entirely on its own dead-reckoned position estimate.

THE SYSTEM

The sonar's distance readings let the robot detect walls and open passages. Three subsystems ran together: a wandering algorithm for exploration, dead-reckoning localization to track position, and a real-time mapping layer that recorded the grid as the robot moved. At dead ends, the robot backtracked along its recorded path to the nearest unexplored branch. Once all reachable space was explored, it retraced the path back to the origin.

HOW IT WORKS

Localization
Dead reckoning uses stride count and current heading, where one stride is three forward tripod gait steps. Each stride advances the robot one grid unit in its current direction, and turns are tracked in software as 90° increments. Drift accumulates over long runs, so a post-turn centering routine (described below) corrected position after each turn.
Path Planning
The robot keeps a stack of visited positions. At a dead end, it pops back through the stack, retracing its exact route until it finds an unexplored branch. This produces a depth-first traversal of the maze without needing a global map upfront.
Mapping
Each visited grid cell is logged to a 2D array along with the robot's heading at entry. Walls are inferred from sonar readings at each cell: if the distance in a given direction falls below a threshold, a wall is recorded on that side. The final map is printed to the terminal at the end of the run.
Wandering
At each junction, the robot uses the sonar to check for open passages to the right, forward, and left. It chooses unexplored directions first, breaking ties in that priority order. If all adjacent cells have been visited, it triggers backtracking. The loop re-evaluates the sonar before every stride.

WHAT BROKE IT

The sonar was reliable in straight corridors but noisy near corners. When the robot over- or under-rotated at a 90° turn, the beam hit the adjacent wall at an angle and returned false distance readings. Two problems followed: the heading error compounded into drift over the next strides, and the false readings produced phantom walls in the map.

We addressed this in two ways. First, a median filter over three consecutive readings ran before every wall-detection decision, which eliminated most false positives without adding meaningful latency. Second, after each turn, a centering routine scanned the adjacent walls and repositioned the robot midway between them.

Over four or five corridor segments, the dead-reckoned position could still slip by a full grid unit, so the return path ended one cell away from the true start. We worked around this by defining "start" as a bounded region rather than a single cell. Within that region, the robot searched for an origin landmark, a sonar-detectable wall pattern unique to the entry corridor, before declaring success.

These fixes improved reliability, but tuning them fully would have required more trials than we had time for, which is why the robot explored about half the maze.
