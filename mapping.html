MAPPING AN
UNKNOWN MAZE

"Three questions every navigation system must answer: Where am I? What's around me? How do I get there?"

Goal

Autonomous maze exploration and return-to-start on a hexapod using only sonar sensing and dead-reckoning — no prior map

Role

Programmer

Skills

Dead Reckoning Sonar Sensing Path Planning Depth-First Search Python Real-Time Mapping

Outcome

Successful maze exploration and backtrack-to-start · sonar noise resolved with median filtering · drift bounded by landmark-based origin detection

Given a completely unknown maze and no prior map, the robot needed to explore every reachable corridor, build a grid representation of what it found, and return to its starting position. The challenge was doing this with only a single front-facing sonar sensor and no external localization — no GPS, no camera, no pre-loaded layout. The system had to decide where to go, track where it had been, and know when it was done, entirely from its own dead-reckoned position estimate.

THE SYSTEM

Given a hexapod robot and an unknown maze, the task was to have the robot explore, build a map of every corridor it traversed, and navigate back to the start. The system had no prior knowledge of the maze layout. A front-facing sonar sensor provided distance readings that the robot used to detect walls and open passages. Three subsystems ran together: a wandering algorithm for exploration, a dead-reckoning localization scheme to track position, and a real-time mapping layer that recorded the grid as the robot moved through it. Once the robot reached a dead end or had fully explored reachable space, it reversed the recorded path back to the origin.

HOW IT WORKS

Localization
Dead reckoning using stride count and heading. Each stride advances the robot one grid unit in the current direction; turns are 90° increments tracked in software. Drift accumulates over long runs but stays bounded within the maze's scale.
Path Planning
The robot keeps a stack of visited positions. On reaching a dead end, it pops back through the stack — retracing its exact route — until it finds an unexplored branch. This gives a depth-first traversal of the maze without any global map being required upfront.
Mapping
Each grid cell visited is logged to a 2D array with the robot's known heading at entry. Wall presence is inferred from sonar readings at each cell: if distance < threshold in a given direction, a wall is recorded on that side. The final map is printed to the terminal at the end of the run.
Wandering
At each junction the robot checks for open passages (right, forward, left) in priority order. It prefers unexplored directions. If all adjacent cells are visited, it triggers backtracking. The wandering loop runs at each stride, re-evaluating sonar before each move.

WHAT BROKE IT

The sonar sensor was reliable in straight corridors but noisy near corners. At 90° turns, the beam would partially clip the adjacent wall and return a false short reading — making the robot think a passage was blocked when it wasn't. We added a median filter over three consecutive readings before any wall-detection decision, which eliminated most false positives without adding meaningful latency.

Drift was the harder problem. Over four or five corridor segments the dead-reckoning position could slip by one full grid unit, causing the backtrack path to terminate one cell off from the true start. We worked around this by defining "start" as a bounded region rather than a single cell, and having the robot search for its origin landmark (a sonar-detectable wall pattern unique to the entry corridor) within that region before declaring success.
